# RC0 连载 IP 与跨媒介改编

IP 是一套被反复讲述仍然认得出的决定：谁想要什么、画面长什么样、哪一种色彩属于这个世界。改编要看得见来源。

## 何时使用

- 把单部剧本扩展成系列、季或可复用模板。
- 设计二创、套用预设、从模板开新草稿时如何保留署名。
- 讨论同一世界观在剧本、分镜、画廊静帧和预设之间如何迁移。
- 审阅标签、作者、等级与作品 id 能否支撑「这是同一部戏的后续」。

## 领域立场

跨媒介不是把同一张封面贴到每个入口。剧本携带因果，分镜携带顺序，预设携带观看方式，画廊携带可以驻足的瞬间，模板携带可被别人接着做的结构。系列靠这些决定的稳定，不靠标题后缀「第二季」。

## 与 RC0 模型的映射

一条可连载的作品至少要能指回：

- 戏剧树：幕、场、镜（`screenplay` / `screenplay_draft`）
- 摄影与色彩：`cinePresetId` 以及预设上的画幅、帧率、色彩空间、LUT
- 公开商品：`TemplateDetail` 的作者、标签、幕场目录
- 作者：`UserProfile` 与作品 id

新的一集是新的剧本或新的模板 id，不是覆盖旧 id。旧作品仍可被打开。模板生成草稿时，草稿记录来源类型，公开页仍指向原作者。

## 创作原则

1. 续集必须改变关系或世界规则的后果。重复上一集的场标题和封面格，不算续集。
2. 世界观约束写成可检查的决定：固定画幅、主 LUT、人物欲望、禁止出现的结局类型。不写无法执行的「氛围圣经」。
3. 改编到静帧时，选出系列里最能独立看懂的转折格进入画廊，而不是导出全部缩略图。
4. 二创可以换场次，若更换主预设，作品标题或标签需要让观众看出这是色彩上的另一支，而不是冒充原作。
5. 系列标签稳定且少。集数信息放在标题或场目录，不把「第一集」写进每一条标签。
6. 来源作者在模板详情和由此创建的作品上可被找到。署名是结构的一部分。

## 互联网创业约束

- 模板是授权结构被复用的方式。复用产生新作品 id，统计归属不要算回原作的点赞。
- 系列的发现方式是下一件作品，不是外部商城。关注作者之后，新的一集应出现在关注流。
- 不在客户端写死授权条款全文或第三方版权文本。需要展示的是作者、来源作品和是否允许作为模板。

## 实现时遵守

- 系列关系若尚无实体，先在领域层表达来源 id，再让市场、草稿和主页读取它。不要只在标题字符串里编码系列。
- 路由继续用作品 id、场 id、帧序号。不发明无法深链的「宇宙页」来代替作品本身。
- 跨功能导航走既有路由常量：模板详情、预设、帧查看器、剧本详情、创建草稿。

## 产出检查

- 续集与原作在因果、画幅和主色彩上的继承关系说得清。
- 原作 id 不被续集覆盖，来源作者找得到。
- 二创换了 LUT 或结构时，观众不会把它误认为原作更新。
- 从模板创建的草稿在发布前仍是草稿，发布后才进入作者自己的作品集。

## 相关技能

单集戏剧用 `rc0-short-drama-writing`，观看方式用 `rc0-cinematography-language` 与 `rc0-color-lut-identity`，复用后的橱窗用 `rc0-template-cover-commerce`，作者署名用 `rc0-creator-persona-art`。
