# RC0 信息流策展

信息流是一种展览走道。算法可以决定顺序，但不能把走道布置成同一种海报的重复。

## 何时使用

- 调整首页「发现 / 关注 / 推荐 / 社区」或探索流。
- 设计 `FeedItem` 的标题、封面、作者、点赞、评论与标签。
- 讨论推荐多样性、关注关系与社区话题如何共存。

## 领域立场

四条流是四种策展理由，不是四套皮肤：

- 发现：观众还没选择作者，靠作品自身的第一格。
- 关注：观众已经选择了人，顺序尊重作者的时间。
- 推荐：在观众可能喜欢的类型里保持差异，避免同一 LUT、同一景别刷屏。
- 社区：话题和回应优先，作品是讨论的现场，不是广告位。

## 与 RC0 模型的映射

`FeedItem`：`title`、`coverUrl`、`authorName`、`authorAvatarUrl`、`likes`、`comments`、`tags`。

首页标签顺序固定为发现、关注、推荐、社区。探索旧路由可以重定向，但策展规则仍按这四种理由区分。

点赞、评论、收藏的通知类型是 `comment`、`like`、`favorite`，它们是流之外的回声，不替代流内的作品呈现。

## 创作原则

1. 封面使用作品的转折格，标题使用作品名。流内不改写标题做点击诱饵。
2. 相邻卡片在类型、画幅或色彩上应有可见差别。同一屏不要出现三张无法区分的封面。
3. 标签帮助划走时的辨认，一张卡片标签要少，且与标题信息不重复。
4. 关注流允许同一作者连续出现，因为这是订阅。发现和推荐不允许同一作者霸屏。
5. 空流要说明这条走道为什么是空的（尚未关注、尚无推荐），并给出回到作品本身的入口，而不是假数据。
6. 社交数字使用真实计数。为零就显示零或安静地不强调，不制造假热度。

## 互联网创业约束

- 推荐的目标是让人看完下一件作品，不是让人停在卡片上。卡片信息必须少到能点进去。
- 社区流可以抬高被讨论的作品，讨论摘要不能盖住画面。
- 不把付费、私信或外部跳转做成流的默认动作。默认动作是打开作品。

## 实现时遵守

- 流数据走 `explore` 或首页对应 Provider，Tab 只切换策展源，不在 Tab 里写排序公式。
- 长列表用 builder，图片缓存，滚动状态不在 `build` 里重置。
- 四条流共享卡片外观，不复制四套页面。差异放在数据与空态文案。

## 产出检查

- 四条流的空态、顺序理由和默认动作彼此不同。
- 同一屏封面可被区分。
- 标题、作者、计数与作品详情一致。
- 没有为了填满列表而混入另一条流的数据。

## 相关技能
