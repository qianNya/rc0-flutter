# RC0 数字画廊与静帧展览

画廊陈列完成的画面。它不是分镜草稿架，也不是模板货架。每一张图都应能单独站住。

## 何时使用

- 设计或调整画廊页、图片网格、大图与分辨率信息。
- 处理 `GalleryImage` 的 `imageUrl`、`width`、`height`、`resolution`、`tag`。
- 决定一张剧照、概念图或静帧如何被观看，而不被裁成商品封面。

## 领域立场

展览尊重原作比例。网格可以整齐，单张作品的比例不能为了整齐而被拉变形。标签是墙上的小说明牌，不是封面标题。

## 与 RC0 模型的映射

`GalleryImage`：

- `width` / `height` 决定陈列比例
- `resolution` 是可选的技术说明
- `tag` 是可选的作品类型或场景说明
- `imageUrl` 是展品本身

剧照若来自分镜，来源帧仍留在 `screenplay_draft` 或帧查看器。画廊只引用可公开展示的图像，不把草稿资产引用直接当成展品模型。

## 创作原则

1. 按原始宽高比布局。竖图、横图、方图可以同场，用间距而不是拉伸统一它们。
2. 一组展览需要观看顺序：从远到近，或从日常到高潮。不要按上传时间假装那是策展。
3. `tag` 写作品内容（夜外、人物、道具），不写「高清」「必看」。
4. `resolution` 只在它帮助判断印刷或放大时出现。缺失时不显示假精度。
5. 大图观看保持安静：画面优先，说明其次。社交计数不属于这一页的第一视界。
6. 失败的图片显示中性占位，不显示破损图标剧院。占位不冒充另一张作品。

## 互联网创业约束

- 画廊是创作者的展厅，可从个人作品进入，但陈列逻辑仍是观看，不是转化漏斗。
- 公开图必须是作者选择展出的版本。草稿缩略图、未完成格不要自动进入画廊。
- 首页快捷入口「图片」进入画廊，不进入模板市场。

## 实现时遵守

- 网格用 `GridView.builder` 或等价 builder，按 `width`/`height` 计算比例。
- 图片缓存与占位沿用共享图片组件，不在 `build` 里计算文件大小。
- 画廊数据走 `gallery` 的 Repository 边界。

## 产出检查

- 没有被拉伸的画面。
- 每张图在无标题时仍可观看；有标签时标签不遮住主体。
- 顺序体现策展，而不是数据库默认序的偶然。
- 草稿与展品的边界清楚。

## 相关技能

色彩一致性用 `rc0-color-lut-identity`，作为商品封面的裁切用 `rc0-template-cover-commerce`，作者展厅入口用 `rc0-creator-persona-art`。
