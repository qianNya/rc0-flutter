# RC0 色彩与 LUT 身份

色彩是作品的身份，也是预设能被反复购买的原因。一套 LUT 是一种世界观，不是一张滤镜封面。

## 何时使用

- 定义或解释 `CinePresetDetail.colorSpace` 与 `lut`。
- 为模板、画廊、信息流封面规定主色、辅色和禁用色。
- 审核同一作品或同一创作者名下画面是否串色。
- 把「电影感」「日系」「赛博」翻译成可执行的色彩约束。

## 领域立场

颜色先服务于辨认，再服务于风格。观众应能在缩略图里认出这是同一部作品。互联网上的风格词很容易空转，RC0 里风格必须落到色彩空间和 LUT 名称上。

## 与 RC0 模型的映射

- 成套色彩属于预设：`CinePresetDetail.colorSpace`、`CinePresetDetail.lut`。
- 帧通过 `DraftFrameData.cinePresetId` 继承这套色彩，不在每一镜单独发明滤镜名。
- 封面与画廊图是色彩的公开样本：`coverUrl`、`GalleryImage`、帧缩略图。

`colorSpace` 使用可交换的标识，例如 `rec709`、`srgb`、`rec2020`。展示层再说明它适合手机还是宽色域。LUT 用稳定名称，名称描述气质与工艺（如印刷、夜戏、日光），不描述「好看」。

## 创作原则

1. 一部作品、一个模板、一次向导发布，只绑定一条主 LUT。局部对比靠布光与景别，不靠第二套滤镜。
2. 肤色与关键道具色在主 LUT 下必须仍可辨认。风格不能吞掉叙事信息。
3. 封面、第一格、预设缩略图使用同一色彩结论，避免市场页和成片像两个作者。
4. 界面强调色服从应用主题 token，不从作品 LUT 里临时取色涂按钮。作品色只出现在作品画面上。
5. 夜戏、雪景、霓虹等极端场景要在 LUT 说明里写清失效条件，例如高饱和霓虹会裁掉肤色。

## 互联网创业约束

- LUT 是创作者可以签名的资产。预设卡片展示缩略图、画幅、帧率，色彩差异靠缩略图本身可见，不靠形容词堆叠。
- 热门模板被二创时，保留原 LUT 作为「原作色彩」，改编若换 LUT 必须在作品上可被看出来源不同。
- 不要把第三方 LUT 文件内容或授权密钥写进仓库。只保存名称、标识和授权状态。

## 实现时遵守

- 色彩字段留在 `cine_preset` 域，帧只存 `cinePresetId`。
- 不在 Widget 里硬编码十六进制作为「品牌 LUT」。应用 chrome 使用 `AppColors` 与主题。
- 图片加载继续走现有缓存组件，调色预览不在 `build` 里做像素运算。

## 产出检查

- 同一 `cinePresetId` 下的帧没有互相矛盾的 LUT 描述。
- 缩略图在深色界面上仍能分离主体与背景。
- 色彩空间标识可持久化、可展示，且与发行屏幕匹配。
- 没有把商业滤镜的密钥或下载地址写进客户端。

## 相关技能

画幅与焦段用 `rc0-cinematography-language`，封面商品图用 `rc0-template-cover-commerce`，画廊陈列用 `rc0-gallery-exhibition`。
