# RC0 生成式创作仪式

向导是一场有顺序的创作仪式：先结构，再画面，最后才发布。生成是草稿的助手，发布是作者的签名。

## 何时使用

- 设计 `create_wizard` 的步骤、进度、结构步与发布步。
- 处理从生成结果写入 `screenplay_draft` 的幕、场、镜。
- 讨论 AIGC 如何进入 RC0，而不把向导做成一次性提示词输入框。
- 审阅草稿来源、同步状态与发布前作者仍能改写的节点。

## 领域立场

生成扩大了草图速度，没有取消作者。仪式的每一步都留下可编辑的戏剧或摄影决定。无法解释的结果留在草稿里，不直接成为公开模板。

## 与 RC0 模型的映射

向导领域目前有 `WizardAct` 与 `WizardScene`（`id`、`title`、`description`）。发布后的完整镜头在草稿帧上生长，而不是在向导步骤里堆满摄影字段。

草稿侧已有来源、同步状态、资产引用，以及帧上的 `acgnImageId`、`acgnImageFileId`、`cinePresetId`。生成图像通过资产引用进入帧，不把模型供应商的密钥写进草稿。

步骤在界面上是进度，在领域上是草稿的不同完整度：结构未完成、结构已可排镜、已选择预设、作者确认发布。

## 创作原则

1. 第一步只问戏剧结构：幕、场、场的一句描述。不在第一步索要滤镜、价格或标签。
2. 生成出的场标题必须可读。空标题、重复标题要在离开结构步之前被作者改掉。
3. 每一场描述只写这一场的冲突或动作，供后续分镜拆格。描述不是提示词仓库。
4. 图像生成结果先成为帧的资产引用，作者确认景别、时长与顺序后，才算这一格完成。
5. 发布步展示即将公开的标题、封面格、预设和场目录。作者明确确认后才离开草稿。
6. 失败的生成保留已写好的结构。网络失败不回退用户已经命名的幕和场。

## 互联网创业约束

- 向导的完成定义是「一件可被别人打开的作品」，不是「一次成功的模型调用」。
- 草稿可以私有，模板市场只接收发布后的结构。未发布草稿不进入发现流。
- 生成成本与等待属于过程反馈，不在步骤文案里催促充值。

## 实现时遵守

- 步骤 Widget 只渲染当前步骤，网络与生成调用放在 UseCase。
- 向导状态与草稿仓储分开：向导收集决定，草稿保存作品。
- 密钥、模型 token 不进入实体、日志和界面。凭证继续走安全存储与拦截器。
- 进度条反映真实步骤，不在生成未结束时提前标成已发布。

## 产出检查

- 作者可以在发布前改每一场标题和描述。
- 生成失败时结构仍在。
- 发布物具备标题、至少一场、以及可展示的封面来源。
- 向导没有把提示词、密钥或未确认草稿送进公开市场。

## 相关技能

场的戏剧质量用 `rc0-short-drama-writing`，拆格用 `rc0-storyboard-sequential-art`，发布后的商品面貌用 `rc0-template-cover-commerce`。
